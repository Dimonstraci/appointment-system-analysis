# 03. Сценарии использования

## UC-01. Записаться на услугу

**Актор:** клиент. **Предусловия:** есть валидный токен роли client, опубликовано расписание. **Триггер:** клиент хочет выбрать время. **Результат:** создана одна CONFIRMED-запись либо показан отказ без записи.

1. Клиент открывает каталог: `GET /services`.
2. Выбирает услугу и локальную дату: `GET /slots?serviceId=…&date=2026-09-10`.
3. Интерфейс показывает специалиста, начало и конец с подписью «Время студии, Europe/Saratov».
4. Клиент выбирает слот и нажимает «Записаться»; интерфейс генерирует UUID для `Idempotency-Key`.
5. API проверяет токен, формат, ключ, доступность и ограничения в транзакции.
6. API сохраняет запись и результат идемпотентности; после commit возвращает 201.
7. Интерфейс показывает ID и время записи. Повторный просмотр использует `GET /appointments/{id}`.

**Альтернативы:**

- A1: слотов нет → 200, пустой массив, предложение выбрать другую дату.
- A2: между шагами 2 и 5 слот заняли → 409 SLOT_UNAVAILABLE; обновить список, не показывать подтверждение.
- A3: ответ потерялся → повторить с исходным ключом и slotId, вернуть сохранённый 201.
- A4: истёк токен → 401, повторная авторизация; после неё тот же ключ для неизвестного результата.
- A5: дата вышла за горизонт / слот начался / услуга отключена → 409 SLOT_UNAVAILABLE.
- A6: неизвестный slotId → 404 NOT_FOUND.

## UC-02. Отменить собственную запись

**Актор:** клиент. **Предусловия:** запись принадлежит клиенту. **Результат:** CANCELLED и слот освобождён либо запись не изменена.

1. Клиент открывает свою запись.
2. Нажимает «Отменить», указывает причину длиной 1–500 символов после trim.
3. API проверяет принадлежность, блокирует строку записи и проверяет статус.
4. Если уже CANCELLED, возвращает 200 без изменений.
5. Для CONFIRMED API сравнивает начало слота с серверным временем: разница должна быть ≥ 2 часов.
6. В одной транзакции сохраняются CANCELLED, cancelledAt, cancelledBy и cancellationReason.
7. После commit API возвращает 200; слот снова доступен, если остальные условия поиска выполняются.

**Отказы:** чужой ID → 404; короткое окно → 409; пустая причина → 422. Повтор корректной отмены возвращает исходную причину. Удаление строки записи не применяется.

## UC-03. Посмотреть день и отменить запись администратором

**Актор:** администратор. **Предусловия:** токен admin. **Результат:** список или отмена с аудитом.

1. Администратор выбирает дату: `GET /admin/appointments?date=…` (любой корректный календарный день).
2. Видит все записи со временем, clientId и статусом; в MVP нет контактных данных клиента.
3. При необходимости вызывает ту же операцию отмены с причиной.
4. Для активной записи достаточно `startsAt > now`; двухчасовой порог не применяется.
5. Система фиксирует subject администратора как cancelledBy.

**Отказы:** роль client → 403 для списка; после начала активной записи → 409. Уже отменённая запись → 200 без новой записи аудита.

## Эскиз экранов и состояний

```text
Выбор услуги → Дата и свободное время → Подтверждение → Карточка записи
                   │                       │                 │
                   └ нет слотов            └ 409: обновить    └ Отмена + причина
                     другая дата              список            → CANCELLED
```

На время POST кнопка блокируется, но сервер не полагается на это для защиты от дублей. При таймауте текст: «Результат пока неизвестен. Повторите проверку»; нельзя утверждать, что запись не создана. Экран администратора содержит дату, список и действия отмены. Это функциональный эскиз, дизайн интерфейса не разрабатывался.
