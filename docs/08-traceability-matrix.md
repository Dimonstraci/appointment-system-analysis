# 08. Матрица трассировки требований

Эта матрица показывает путь от бизнес-цели до проверки реализации. Она не доказывает, что система уже протестирована: сервер и тестовая БД в кейсе не развёрнуты. Статус сценариев указан в [приёмке](07-acceptance.md).

| Бизнес-цель | Требование и правило | Реализация и контракт | Ограничение данных | Критерий приёмки |
|---|---|---|---|---|
| BG-01. Исключить двойную запись | FR-03, FR-08, NFR-02; один активный слот — одна `CONFIRMED` запись | `POST /appointments`; транзакция, `FOR UPDATE`, `Idempotency-Key` | частичный `UNIQUE(slot_id) WHERE status = 'CONFIRMED'`; результат ключа хранится отдельно | TC-03–06, TC-21, TC-25–26 |
| BG-01. Корректно обработать параллельность | Повторно проверять доступность после блокировки; не раскрывать техническую ошибку БД | `409 SLOT_UNAVAILABLE`; стабильный бизнес-код и `requestId` | блокировка строки `slot`; уникальность как последняя защита | TC-04, TC-20–21 |
| BG-02. Дать клиенту самостоятельную запись | FR-01, FR-02; активная услуга и свободный слот на локальную дату | `GET /services`, `GET /slots`; допустимый горизонт 30 дат | `service.is_active`, время слота и отсутствие активной записи | TC-01–02, TC-16, TC-18–20, TC-23–24 |
| BG-02. Не раскрывать чужие записи | FR-04, NFR-03; клиент видит только свои данные | `GET /appointments/{id}` возвращает `404` при чужой записи | `appointment.client_id` сравнивается с subject токена | TC-07, TC-14 |
| BG-03. Сократить ручную работу с отменами | FR-05, FR-07, FR-09; клиент отменяет за 2 часа, admin — до начала | `POST /appointments/{id}/cancel`; причина обязательна | история отмены сохраняется; статус `CANCELLED` терминален | TC-08–13 |
| BG-03. Дать администратору обзор дня | FR-06; только роль `admin` | `GET /admin/appointments?date=` | записи сортируются по времени начала и ID | TC-15, TC-22 |
| Эксплуатационная наблюдаемость | NFR-05, NFR-06; ответ можно сопоставить с журналом | `requestId` в ответе; ошибки без SQL и stack trace | не требуется отдельная сущность в MVP | проверка логов и ручной UX-тест на реализации |

## Границы трассировки

- Нагрузочная цель NFR-01 требует отдельного протокола и развёрнутого стенда; она не подтверждается чтением спецификации.
- Метрики BG-02 и BG-03 оцениваются после пилота: до него это гипотезы, а не заявленный эффект.
- При добавлении оплаты, уведомлений, филиалов или управления расписанием матрица должна быть дополнена до начала реализации инкремента.
