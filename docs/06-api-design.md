# 06. Контракт API

Источник схем запросов и ответов — [OpenAPI 3.0.3](../api/openapi.json). В JSON используется тот же формат OpenAPI, что и в YAML. [HTTP-примеры](../api/examples.http) не содержат действующего токена или адреса сервера.

| Метод | Путь | Назначение | Успех |
|---|---|---|---|
| GET | /services | Активные услуги | 200 массив |
| GET | /slots | Доступные слоты услуги на дату | 200 массив |
| POST | /appointments | Создать запись; Idempotency-Key обязателен | 201 Appointment |
| GET | /appointments/{id} | Своя запись / любая для admin | 200 Appointment |
| POST | /appointments/{id}/cancel | Отмена с причиной | 200 Appointment |
| GET | /admin/appointments | Все записи на дату начала слота | 200 массив |

Пути в таблице относительны `/v1`. Пагинация не включена: одна студия, запросы ограничены одним днём. При расширении до сети требуется пересмотреть контракт.

## Общие соглашения

- Bearer-токен проверяется через доверенный IdP: подпись, issuer, audience, срок; его конкретная интеграция вне кейса.
- Данные пользователя берутся из subject и роли токена. Роли `client` и `admin` взаимоисключающие для данного запроса.
- Некорректный JSON → 400 INVALID_JSON; нарушенная схема/параметр → 422 VALIDATION_ERROR. Неизвестные поля тела отклоняются.
- Недействительный/отсутствующий токен → 401 UNAUTHORIZED; неверная роль → 403 FORBIDDEN.
- Неизвестная услуга при поиске слотов → 404 NOT_FOUND; известная неактивная → 200 [].
- Недоступный существующий слот при создании → 409 SLOT_UNAVAILABLE; несуществующий → 404 NOT_FOUND.
- Чужая запись не раскрывается: 404 NOT_FOUND, даже если ID существует.
- Внутренняя ошибка → 500 INTERNAL_ERROR, без деталей SQL. При неизвестном результате клиент повторяет создание с тем же ключом.
- `requestId` генерируется сервером для корреляции. Бизнес-код ошибки стабилен, message можно локализовать.

Приоритет: аутентификация → роль → синтаксис/валидация → принадлежность записи → бизнес-правило. Для создания успешный повтор ключа обрабатывается раньше доступности слота. Для отмены CANCELLED проверяется раньше окна времени, после авторизации и валидации причины.

## Пример конфликта

```json
{
  "code": "SLOT_UNAVAILABLE",
  "message": "Выбранное время уже недоступно. Обновите список слотов.",
  "requestId": "demo-request-002"
}
```

Идемпотентность, блокировки и транзакционные границы: [алгоритм](04-processes-and-uml.md). Контракт описывает ожидаемую реализацию; API не запущен.
