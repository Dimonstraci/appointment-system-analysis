# Бизнес-процессы (BPMN)

Диаграммы показывают TO-BE процесс одной студии. Пулы и дорожки отражают участников, события — результат команды. Для редактирования в BPMN-инструменте используется [booking.bpmn](booking.bpmn); Mermaid ниже даёт быстрый просмотр прямо в GitHub.

## BP-01. Онлайн-запись на свободный слот

```mermaid
flowchart LR
    subgraph ClientPool[Пул: Клиент]
        C1((Старт)) --> C2[Выбрать услугу и дату]
        C2 --> C3[Выбрать слот]
        C3 --> C4[Отправить команду записи]
        C8[Показать подтверждение]
        C9[Показать конфликт и обновить слоты]
        C4 --> C5((Ожидание результата))
        C5 --> C8
        C5 --> C9
    end

    subgraph SystemPool[Пул: Slotly]
        S1[Получить GET /slots]
        S2[Проверить токен, схему и Idempotency-Key]
        S3{Повтор ключа?}
        S4[Вернуть сохранённый 201]
        S5[Заблокировать слот и проверить доступность]
        S6{Слот доступен?}
        S7[Создать CONFIRMED и результат ключа\nв одной транзакции]
        S8[COMMIT]
        S9[Вернуть 409 SLOT_UNAVAILABLE]
        S1 --> S2 --> S3
        S3 -->|Да, тот же slotId| S4
        S3 -->|Нет| S5 --> S6
        S6 -->|Да| S7 --> S8
        S6 -->|Нет| S9
    end

    C2 -. HTTP GET .-> S1
    C4 -. HTTP POST .-> S2
    S4 -. 201 .-> C5
    S8 -. 201 .-> C5
    S9 -. 409 .-> C5
```

## BP-02. Отмена записи

```mermaid
flowchart LR
    subgraph Customer[Пул: Клиент]
        A1((Открыть запись)) --> A2[Указать причину]
        A2 --> A3[Отправить отмену]
        A7[Показать CANCELLED]
        A8[Показать отказ]
    end
    subgraph Cancellation[Пул: Slotly]
        B1[Авторизовать и проверить владельца]
        B2{Статус CANCELLED?}
        B3[Вернуть 200 без изменений]
        B4[Заблокировать запись]
        B5{Окно отмены разрешено?}
        B6[Сохранить статус и аудит\nв одной транзакции]
        B7[Вернуть 409 CANCELLATION_WINDOW_CLOSED]
        B1 --> B2
        B2 -->|Да| B3
        B2 -->|Нет| B4 --> B5
        B5 -->|Да| B6
        B5 -->|Нет| B7
    end
    A3 -. POST /cancel .-> B1
    B3 -. 200 .-> A7
    B6 -. 200 .-> A7
    B7 -. 409 .-> A8
```

## Правила процесса

- Получение свободных слотов не меняет состояние базы.
- Ветвление «доступен ли слот» выполняется после блокировки и повторной проверки серверного времени.
- При успешной записи фиксируются `appointment` и `idempotency_result`; при отказе изменения откатываются.
- Повтор отмены уже отменённой записи идемпотентен и не создаёт новую запись аудита.
- Администратор использует тот же процесс отмены, но проверяет право `admin` и условие `startsAt > now` вместо двухчасового окна клиента.

## Границы BPMN-модели

Модель описывает orchestration API-команды и не является исполняемой схемой workflow-движка. Регистрация, оплата, уведомления и импорт расписания находятся за границами процесса.
